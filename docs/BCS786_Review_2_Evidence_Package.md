## 2. Methodology

Flash follows an agent-assisted workflow:

1. The user submits a natural-language request in the dashboard.
2. The server authenticates the user and resolves a Gmail access token.
3. The AI model selects an appropriate Gmail or Calendar tool.
4. Read operations return structured data and are rendered as cards.
5. Write operations that affect user data require a draft or confirmation UI before execution.
6. Approved operations are sent through authenticated server routes or Gmail tools.
7. Conversation messages are persisted in Supabase for later review.

The main implementation uses Next.js 16 App Router, React, TypeScript, Supabase, the Pi AI SDK, Gmail REST APIs, Google Calendar REST APIs, Framer Motion, and Tailwind CSS. OAuth tokens are kept server-side and refreshed before Gmail operations.

## 5. Viva Questions and Short Answers

**Why use natural language?** It reduces the need for users to learn Gmail filters and exposes one workflow for search, reading, drafting, and calendar tasks.

**Why require confirmation?** Sending mail and changing calendar data are consequential actions. Confirmation preserves user control and reduces accidental mutations.

**How are tokens protected?** API routes authenticate the Supabase user and resolve Gmail access server-side; the browser does not receive the refresh token.

**What is the main limitation?** The current prototype needs broader automated testing, rate limiting, audit logging, and a measured user evaluation.

**How is the system extensible?** New Gmail or Calendar capabilities can be exposed as typed tools and rendered through the existing UI-card event stream.
